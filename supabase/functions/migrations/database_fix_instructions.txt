DATABASE FIX INSTRUCTIONS - ROLE NAME UPDATE
=============================================

PROBLEM:
--------
The navigation flow is failing because there's a mismatch between the frontend code
that uses 'admin_it' role and the database that still uses 'admin' role in RLS policies
and constraints.

ERROR SYMPTOM:
---------------
When users try to select a role via /api/profile/select-role, they get:
"statusCode": 500, "message": "Gagal menyimpan role."

ROOT CAUSE:
-----------
The database RLS policies and constraints still reference the old role name 'admin',
but the API endpoint and frontend are trying to use 'admin_it'.

WHAT NEEDS TO BE FIXED:
-----------------------

1. TABLE CONSTRAINT (profiles table):
   CURRENT: role in ('admin', 'ustadz')
   SHOULD BE: role in ('admin_it', 'ustadz')

2. RLS POLICIES that need updating:
   - "Admin can verify or reject" policy (line ~225)
   - "Admin can delete" policy (line ~262) 
   - "Staff can read all questions" policy (line ~276)
   - "Users can update own role" policy (line ~320)

3. EXISTING DATA:
   - Update any profiles with role='admin' to role='admin_it'

SQL COMMANDS TO RUN:
---------------------

-- 1. Update table constraint
ALTER TABLE public.profiles DROP CONSTRAINT IF EXISTS valid_role;
ALTER TABLE public.profiles ADD CONSTRAINT valid_role 
  CHECK (role IS NULL OR role IN ('admin_it', 'ustadz'));

-- 2. Update existing data
UPDATE public.profiles 
SET role = 'admin_it' 
WHERE role = 'admin';

-- 3. Update RLS policies (drop and recreate)
DROP POLICY IF EXISTS "Admin can verify or reject" ON public.questions;
CREATE POLICY "Admin can verify or reject"
  ON public.questions
  FOR UPDATE
  USING (
    EXISTS (
      SELECT 1 FROM public.profiles
      WHERE profiles.id = auth.uid()
        AND profiles.role = 'admin_it'
    )
    AND status NOT IN ('answered')
  )
  WITH CHECK (
    status IN ('verified', 'rejected')
    AND answer IS NOT DISTINCT FROM (SELECT answer FROM public.questions WHERE id = questions.id)
  );

DROP POLICY IF EXISTS "Admin can delete" ON public.questions;
CREATE POLICY "Admin can delete"
  ON public.questions
  FOR DELETE
  USING (
    EXISTS (
      SELECT 1 FROM public.profiles
      WHERE profiles.id = auth.uid()
        AND profiles.role = 'admin_it'
    )
  );

DROP POLICY IF EXISTS "Staff can read all questions" ON public.questions;
CREATE POLICY "Staff can read all questions"
  ON public.questions
  FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM public.profiles
      WHERE profiles.id = auth.uid()
        AND profiles.role IN ('admin_it', 'ustadz')
    )
  );

DROP POLICY IF EXISTS "Users can update own role" ON public.profiles;
CREATE POLICY "Users can update own role"
  ON public.profiles
  FOR UPDATE
  USING (auth.uid() = id)
  WITH CHECK (
    role IN ('admin_it', 'ustadz')
  );

VERIFICATION:
-------------
-- Check updated roles
SELECT id, role, full_name, email 
FROM public.profiles 
WHERE role IS NOT NULL 
ORDER BY created_at DESC;

-- Count by role
SELECT role, COUNT(*) as count
FROM public.profiles 
WHERE role IS NOT NULL 
GROUP BY role;

EXPECTED RESULT:
----------------
After running these commands:
- Users should be able to select 'admin_it' role successfully
- The navigation flow should work: login → select-role → dashboard
- No more "Gagal menyimpan role" errors
